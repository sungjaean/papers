## Executive Summary (핵심 요약)

- **핵심 명제**: *"더 많은 에이전트를 투입하면 항상 성능이 향상되는가? (More agents is all you need?)"*라는 통념에 반박하며, 에이전트 시스템의 성능은 **작업 구조(Task Structure)**, **단일 에이전트 기준 성능(Baseline)**, **조율 아키텍처(Coordination Architecture)** 간의 **정합성(Alignment)**에 의해 결정된다는 정량적 원리를 규명함.
- **통제된 실험**: 프롬프트, 도구, 총 컴퓨팅 예산(평균 ~4,800 토큰)을 일치시킨 **260개 제어 설정** 하에, **3대 LLM 제품군**(OpenAI, Google, Anthropic), **5개 표준 아키텍처**(SAS 및 4개 MAS), **6개 실제 에이전틱 벤치마크**를 평가.
- **주요 발견 3가지**:
  1. **역량 포화 한계 (Capability Saturation, $\beta = -0.236, p=0.004$)**: 단일 에이전트(SAS) 성능이 **약 45%**를 넘어서면, 에이전트를 추가했을 때 조율 비용이 이점보다 커져 오히려 성능이 하락함.
  2. **작업 분해성 대 순차적 의존성**: 병렬 분해가 가능한 금융 분석(Finance-Agent)에서는 **최대 +80.8%** 향상된 반면, 순차적 제약이 강한 계획 작업(PlanCraft)에서는 모든 멀티 에이전트가 **-39.1% ~ -70.0% 폭락**. 전체 벤치마크 평균 개선율은 **-0.3%**.
  3. **도구-조율 상충 (Tool-Coordination Trade-off, $\beta = -0.096, p=0.002$)**: 환경 도구 수($T$)가 많을수록 멀티 에이전트의 조율 비효율 페널티가 급격히 가중됨.
  4. **오류 증폭 격차 (Error Amplification)**: 독립형(Independent)은 오류를 **17.2배** 증폭시키는 반면, 중앙집중형(Centralized)은 오케스트레이터의 검증 병목 덕분에 **4.4배**로 억제함.
- **예측 모델 제공**: 측정 가능한 시스템/작업 지표를 기반으로 미지의 작업 설정에서 최적의 아키텍처를 **87% 정확도**로 예측하는 스케일링 회귀 모델($R^2_{\text{CV}} = 0.373 \sim 0.413$) 제시.

## 1. 연구 배경 및 문제의식 (Motivation)

### 1.1 기존 연구의 한계
- 기존 LLM 에이전트 평가(MMLU, HumanEval 등)는 **정적(Non-agentic, single-shot)** 환경에 치우쳐 있어, 에이전트 수를 늘리면 성능이 단조 증가하는 것처럼 보이는 착시를 유발함.
- 프롬프트, 도구, 토큰 예산이 연구마다 달라 **아키텍처 자체의 순수한 효과**와 **구현 디테일의 효과**가 혼재되어 있었음.
- 실패/성공 과정의 동역학(조율 오버헤드, 오류 전파, 정보 전달 효율)에 대한 체계적 측정이 결여됨.

### 1.2 "Agentic Task"의 정의
본 논문은 진정한 에이전트 역량을 평가하기 위해 다음 3대 조건을 만족하는 환경을 대상으로 정의함:
1. **순차적 상호의존성 (Sequential Interdependence)**: 이후 행동이 이전 관찰에 종속되며 단일 추론(one-shot)으로 해결 불가.
2. **부분 관측성 (Partial Observability)**: 상태 정보가 숨겨져 있어 도구 호출 및 능동적 질의를 통해서만 획득 가능.
3. **적응적 전략 수정 (Adaptive Strategy Formation)**: 환경 피드백을 통해 내부 믿음(belief)과 전략을 동적으로 갱신.

## 2. 실험 프레임워크 (Experimental Setup)

공정한 인과 관계 분리를 위해 **동일 프롬프트, 동일 도구 API, 동일 총 토큰 예산**을 엄격히 통제함.

### 2.1 5개 표준 아키텍처 (Ablation Design)
| 아키텍처 | 설명 | 통신 구조 | 주요 특성 |
|---|---|---|---|
| **SAS (Single-Agent)** | 단일 에이전트 기준 모델 | 없음 ($O(k)$) | 통신 비용 0, 문맥 통합 극대화, 분해/검증 역량 제한 |
| **Independent MAS** | 상호 통신 없는 병렬 앙상블 | 에이전트 $\to$ 집계기 | 병렬 탐색 극대화, 검증 부재로 오류 전파에 취약 |
| **Centralized MAS** | 중앙 오케스트레이터가 작업 분배 및 검증 | 오케스트레이터 $\leftrightarrow$ 작업자 | 계층적 검증으로 오류 차단, 오케스트레이터 병목 발생 |
| **Decentralized MAS** | 에이전트 간 직접 토론 및 다수결 합의 | All-to-All (P2P) | 동료 간 정보 융합 우수, 토론 라운드로 인한 오버헤드 |
| **Hybrid MAS** | 중앙 오케스트레이터 + 제한된 피어 간 통신 | 계층 + 측면 통신 | 통제력과 유연성 결합, 프로토콜 복잡도 매우 높음 |

### 2.2 6개 에이전틱 벤치마크 ($N = 260$ configurations)
1. **BrowseComp-Plus**: 다중 웹사이트 탐색, 정보 추출, 교차 페이지 합성 (동적 웹)
2. **Finance-Agent**: SEC 공시 분석, 재무 모델링, 리스크 평가 (구조화/병렬 분해 가능)
3. **PlanCraft**: 마인크래프트 내 순차적 아이템 제작 및 시공간 제약 계획 수립 (엄격한 순차 의존성)
4. **Workbench**: 비즈니스 워크플로우 자동화, 도구 선택 및 코드 실행 (**도구 수 16개**)
5. **SWE-bench Verified**: GitHub 실제 이슈 해결 및 코드베이스 수정 (도구 수 7개, Docker 평가)
6. **Terminal-Bench**: 시스템 관리, 보안, 머신러닝 CLI 명령 수행 (도구 수 2개)

### 2.3 3대 LLM 제품군 & 지능 지수 (Intelligence Index: 42 ~ 71)
- **OpenAI**: GPT-5-nano, GPT-5-mini, GPT-5
- **Google**: Gemini-2.0 Flash, Gemini-2.5 Flash, Gemini-2.5 Pro
- **Anthropic**: Claude Sonnet 3.7, Claude Sonnet 4, Claude Sonnet 4.5

## 3. 핵심 결과 및 분석 (Key Findings)

### 3.1 벤치마크별 상반된 결과: 분해성 vs 순차성
전체 벤치마크 평균 MAS 개선율은 **-0.3%** ($\sigma = 37.5\%$)로, 멀티 에이전트가 만병통치약이 아님을 증명:

```
[Finance-Agent]       Centralized: +80.8%  | Decentralized: +74.5%  | Hybrid: +73.1%
[BrowseComp-Plus]     Decentralized: +9.2% | Centralized: +0.2%    | Independent: -35.0%
[Workbench]           Decentralized: +5.6% | Centralized: -1.2%    | Hybrid: -1.2%
[Terminal-Bench]      Independent: +1.7%   | Centralized: -19.2%   |
[SWE-bench Verified]  Hybrid: -2.1%        | Centralized: -3.1%    | Independent: -14.9%
[PlanCraft]           Hybrid: -39.1%       | Centralized: -50.3%   | Independent: -70.0%
```

- **Finance-Agent (+80.8% 대폭 상승)**:
  - '규제 분석', '재무제표 확인', '운영 리스크 평가' 등 하위 과제가 독립적 정보 스트림으로 자연스럽게 분해됨.
  - 각 에이전트가 병렬로 정보를 수집하고 중앙에서 종합함으로써 정보 이득($\Delta \mathcal{I} = 1.4\text{ bits}$) 극대화.
- **PlanCraft (-70.0% 폭락)**:
  - 마인크래프트 제작은 "레시피 검색 $\to$ 재료 이동 $\to$ 제작"이라는 엄격한 순차적 단계를 가짐.
  - 멀티 에이전트 시스템이 이를 불필요하게 '레시피 조사 에이전트', '인벤토리 확인 에이전트', '제작 에이전트'로 쪼개면서 쓸데없는 조율 메시지만 남발하고 한정된 토큰 예산을 소진함.

### 3.2 아키텍처별 조율 지표 및 효율성 비교

| 메트릭 (전체 260 설정 평균) | SAS (단일) | Independent | Decentralized | Centralized | Hybrid |
|---|:---:|:---:|:---:|:---:|:---:|
| **성공률 (Success Rate)** | **0.466** | 0.370 | **0.477** | 0.463 | 0.452 |
| **추론 턴 수 (Turns)** | **7.2** | 11.4 | 26.1 | 27.7 | 44.3 |
| **조율 오버헤드 (Overhead %)** | **0%** | 58% | 263% | 285% | 515% |
| **메시지 밀도 ($c$, msg/turn)** | 0.00 | 0.00 | **0.41** | 0.39 | 0.24 |
| **중복도 ($R$, redundancy)** | 0.00 | 0.48 | 0.50 | 0.41 | 0.46 |
| **조율 효율성 ($E_c$)** | **0.466** | 0.234 | 0.132 | 0.120 | 0.074 |
| **추적 오류 증폭 ($A_e^{\text{trace}}$)** | **1.0$\times$** | **17.2$\times$** | 7.8$\times$ | **4.4$\times$** | 5.1$\times$ |
| **1천 토큰당 성공 건수** | **67.7** | 42.4 | 23.9 | 21.5 | 13.6 |

- **토큰 경제성**: 단일 에이전트(SAS)는 1,000 토큰당 67.7회 성공을 달성하지만, Hybrid는 13.6회로 **5배 비효율적**.
- **오류 증폭 격차**: Independent는 상호 검증이 없어 한 에이전트의 실수가 최종 결과물로 직결되어 **17.2배** 폭증. Centralized는 오케스트레이터가 걸러내어 **4.4배**로 방어.

## 4. 정량적 스케일링 법칙 (Quantitative Scaling Principles)

저자들은 성능($P$)을 설명하는 다변량 회귀 모형을 유도함 ($R^2_{\text{CV}} = 0.373$, ACI 적용 시 $R^2_{\text{CV}} = 0.413$):

$$P = \beta_0 + \beta_1 (I - \bar{I}) + \beta_3 \log(1+T) + \beta_4 \log(1+n_a) + \beta_{10} P_{\text{SA}} + \beta_{16} (E_c \times T) + \beta_{17} (P_{\text{SA}} \times \log(1+n_a)) + \dots$$

### 4.1 핵심 회귀 계수와 시사점

1. **역량 포화 (Baseline Paradox, $\hat{\beta}_{17} = -0.236, p = 0.004$)**:
   - 단일 에이전트 성능($P_{\text{SA}}$)이 높을수록 에이전트 추가($\log(1+n_a)$) 시 성능에 음(-)의 영향.
   - 단일-멀티 분기점 임계값:
     $$P_{\text{SA}}^* = -\frac{\hat{\beta}_4}{\hat{\beta}_{17}} \approx \frac{0.040}{0.236} \approx \mathbf{0.45 \text{ (45\%)}}$$
   - **단일 에이전트 성공률이 45% 이상인 과제는 멀티 에이전트를 도입하면 오히려 손해**!
2. **도구-효율성 상충 ($\hat{\beta}_{16} = -0.096, p = 0.002$)**:
   - 도구 수($T$)가 증가할수록 조율 효율($E_c$) 저하 페널티가 커짐. 도구가 많은 복잡한 환경에서는 에이전트 간 컨텍스트 전달 과정에서 도구 조율 능력이 희석됨.
3. **지능의 선형적 효과 ($\hat{\beta}_1 = 0.126, p = 0.008$)**:
   - 기본 모델 역량이 높을수록 선형적으로 성능이 향상됨. 그러나 2차항($I^2$)은 유의하지 않아($p=0.977$), 초선형적 '창발적 급상승'은 관찰되지 않음.
4. **추론 턴 수의 거듭제곱 법칙 (Power-law Turn Scaling)**:
   $$T = 2.72 \times (n_a + 0.5)^{1.724} \quad (R^2 = 0.974)$$
   - 에이전트 수가 늘어남에 따라 통신 턴 수가 초선형($1.724 > 1$)으로 폭발. 3~4개 에이전트를 넘어가면 개별 에이전트에 할당되는 토큰이 극도로 줄어 추론 품질이 붕괴됨.

## 5. 실무 아키텍처 선택 의사결정 가이드 (Decision Matrix)

논문의 프레임워크는 미지 구성에 대해 **87%의 정확도**로 최적 아키텍처를 예측함:

```
                      [태스크 분석]
                           │
             단일 에이전트 성공률 (P_SA)
              ┌────────────┴────────────┐
          P_SA ≥ 45%                 P_SA < 45%
              │                         │
     [Single-Agent (SAS)]        태스크 분해 구조 분석
     - SWE-bench 등              ┌──────┴──────┐
     - 고성능 베이스 모델       엄격한 순차성     병렬 분해 가능
                                 │              │
                        [Single-Agent (SAS)]    도구 복잡도 (T)
                        - PlanCraft 등         ┌─────┴─────┐
                                            도구 많음      도구 적음
                                            (T ≥ 10)      (T < 10)
                                               │              │
                                         [Decentralized] [Centralized]
                                         - Workbench     - Finance-Agent
                                         - 동료 간 토론   - 중앙 오케스트레이션
```

1. **Single-Agent System (SAS) 추천**:
   - 모델의 기본 성능이 충분히 높은 경우 ($P_{\text{SA}} \ge 45\%$).
   - 작업이 엄격한 순차적 제약조건을 가지는 경우 (제작 계획, 순차 디버깅).
   - 토큰 비용과 지연시간(Latency)이 매우 중요한 실시간 서비스.
2. **Centralized MAS 추천**:
   - 다각도의 정보 수집 및 독립적 분석이 가능하고 정밀한 교차 검증이 필요한 경우 (금융/법률 분석, 시장 리서치).
   - 오류 전파가 치명적이라 오케스트레이터의 엄격한 검증 필터가 필수적인 경우.
3. **Decentralized MAS 추천**:
   - 고차원 탐색 공간에서 다양한 가설 탐색 및 동료 간 합의가 유리한 경우 (오픈엔드 웹 탐색, 복잡한 비즈니스 도구 조율).
4. **Independent MAS 지양**:
   - 검증 메커니즘이 없어 오류가 $17.2\times$ 증폭되므로, 단순 다수결이 통하지 않는 복잡한 에이전틱 작업에는 부적합.

## 6. LLM 제품군별 특성 (Family Signatures)

- **OpenAI (GPT-5 계열)**: 중앙집중형 및 하이브리드 구성에서 일관된 성능 향상. 구조화된 메시지 전달 및 오케스트레이션 정합성이 뛰어남.
- **Anthropic (Claude 계열)**: 중앙집중형에서 가장 안정적이고 낮은 분산(SD=2.3%)을 보이나, 조율 오버헤드에 민감하여 비용 효율 최적화가 필요함.
- **Google (Gemini 계열)**: 토폴로지 전반에서 균형 잡힌 비용-효율 곡선을 보임.

## 7. 한계점 및 향후 연구 과제 (Limitations)

1. **팀 규모 한계**: 9개 에이전트까지 테스트했으나, 3~4개 이상부터는 통신 오버헤드로 인한 효율 급감이 두드러짐. 대규모 에이전트 집단의 자율 분업 가능성은 미해결.
2. **이종(Heterogeneous) 모델 조합의 한계**: 고성능-저성능 모델을 섞는 실험에서 역량 포화 한계를 극복하지 못함 (중앙집중형에서 고성능 단일 대비 12.6%p 하락).
3. **자연어 토큰 직렬화 병목**: 모든 조율이 자연어 토큰으로 이루어져 비용/지연 발생. 향후 잠재 공간(Latent space) 통신 또는 활성화 공유(Activation sharing) 연구 필요.

## 8. 최종 결론

> **"무작정 에이전트를 늘리는 것은 해결책이 아니다."**  
> 진정한 시스템 확장을 위해서는 **(1) 문제의 순차적/병렬적 구조 파악**, **(2) 단일 에이전트의 역량 포화 여부 진단**, **(3) 오류 차단 검증 구조 설계**가 선행되어야 하며, 본 논문의 스케일링 법칙은 이를 정량적으로 설계할 수 있는 실무적 나침반을 제공한다.
