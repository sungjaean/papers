- **논문 제목**: Decentralized Multi-Agent Systems with Shared Context (공유 컨텍스트를 활용한 탈중앙화 다중 에이전트 시스템)

## 1. Executive Summary (핵심 요약)

기존 대규모 언어 모델 기반 다중 에이전트 시스템(MAS)은 메인 제어 에이전트가 작업을 분할·할당하고 결과를 취합하는 **중앙 집중식 오케스트레이션(Centralized Orchestration)**에 의존했습니다. 그러나 서브태스크와 에이전트 수가 증가할수록 중앙 제어기가 직렬화된 통신 병목이 되고, 정보를 취합·재전송하는 과정에서 중요한 세부사항이나 실패 경험, 제약조건이 희석·왜곡되는 치명적 한계가 발생합니다.

본 논문은 이러한 중앙 집중식 병목을 해결하기 위해 **탈중앙화 언어 모델 프레임워크(DeLM)**을 제안합니다. DeLM은 중앙 컨트롤러를 없애고, **병렬 에이전트(Parallel Agents)**들이 **작업 큐(Task Queue)**에서 비동기적으로 작업을 가져와 수행한 뒤, 그 결과를 검증하여 **검증된 공유 컨텍스트(Shared Context)**에 기록하는 **상태 기반(State-based) 비동기 협업 구조**를 구축합니다.

### 주요 성과
1. **SWE-bench Verified (소프트웨어 엔지니어링 / 테스트 타임 스케일링)**:
   - Gemini 3 Flash 기준 **Avg.@1 65.7%**, **Pass@4 77.4%**를 기록하며 기존 최강 베이스라인(AOrchestra-Parallel) 대비 최대 10.5%p 향상.
   - 그러면서도 작업당 비용은 **$0.12**로 기존 대비 **약 50% 절감**.
2. **LongBench-v2 Multi-Doc QA (긴 문맥 다중 문서 추론)**:
   - 4대 최신 프론티어 모델(GPT-5.4, Claude Sonnet 4.6, Gemini 3 Flash, DeepSeek-V4-Pro) 전반에서 최고 평균 정확도를 달성하며 베이스라인 대비 최대 5.7%p 향상.
3. **OOLONG (정형 집계 추론 / RLM 결합)**:
   - 코드 실행 기반의 RLM(Recursive Language Model)과 결합했을 때 양쪽의 장점을 결합하여 **64.0% 정확도 및 최저 비용($0.40)** 달성.

## 2. 연구 배경 및 기존 MAS의 문제점

### 2.1 다중 에이전트 시스템(MAS)의 필요성
복잡한 작업을 단일 LLM 호출로 끝내는 대신, 문제를 서브태스크로 분할하여 병렬로 탐색하고 결과를 종합하는 MAS는 두 가지 핵심 분야에서 필수적입니다:
1. **테스트 타임 스케일링(Test-Time Scaling)**: 여러 가설이나 추론 경로를 병렬로 탐색하면서 유용한 중간 진전을 공유.
2. **긴 문맥 추론(Long-Context Reasoning)**: 여러 문서나 증거 클러스터를 병렬로 검토하고 통합.

### 2.2 기존 중앙 집중식 MAS의 한계 (The Centralized Bottleneck)
Claude Code Subagents, Kimi Agent Swarm, AOrchestra 등 대부분의 최신 MAS는 중앙 메인 에이전트가 서브 에이전트들을 관리하는 **동기식 Scatter-Gather 루프** 방식을 채택합니다.

```
[기존 중앙 집중식 (Prompt-Routed)]
       ┌───────────────┐
       │   Main Agent  │ ◄── [통신 병목, 정보 왜곡/누락, 가장 느린 워커 대기]
       └──┬─────┬─────┬┘
          │     │     │  (프롬프트로 분배 및 동기 취합)
          ▼     ▼     ▼
        Sub1  Sub2   Sub3
```

1. **통신 및 통합 병목 (Serialized Bottleneck)**:
   - 모든 발견, 실패, 중간 해결책이 메인 에이전트로 반환되어야 하며, 메인 에이전트가 이를 병합하고 다시 다른 에이전트에게 프롬프트로 전송해야 함. 에이전트 수가 늘어날수록 메인 에이전트의 컨텍스트와 처리량이 포화됨.
2. **정보 희석 및 제약조건 손실 (Information Dilution & Distortion)**:
   - 메인 에이전트가 결과를 재요약하고 라우팅하는 과정에서 세부적인 제약조건이나 중요한 실패 교훈이 누락되거나 왜곡됨.
3. **동기식 지연 (Straggler Problem)**:
   - 배치 내 가장 느린 워커의 작업이 끝날 때까지 전체 루프가 대기해야 함.
4. **긴 문맥 사전 할당(Pre-assignment) 오류**:
   - 증거의 관련성을 알기도 전에 메인 에이전트가 하위 에이전트에게 문서 조각을 임의 분배하여, 문맥 부족으로 인한 빈번한 제어권 핑퐁이 발생함.

## 3. 제안 방법론: DeLM (Decentralized Language Models)

DeLM은 조율(Coordination)의 방식을 **프롬프트 라우팅(Prompt-routed)**에서 **공유 상태(State-based)** 기반으로 전환합니다.

```
[DeLM: 탈중앙화 공유 컨텍스트 구조]
              ┌──────────────────────────┐
              │  Task Queue (작업 큐 T)  │
              └───────┬──────────┬───────┘
          asyn claims │          │ asyn claims
                      ▼          ▼
                 [Agent 1]    [Agent 2]
                      │          │ 
                      ▼          ▼
             [Compress & Admission-Time Verification]
                      │          │ (검증 통과한 Gist만 커밋)
                      ▼          ▼
              ┌──────────────────────────┐
              │ Shared Context (공유 C)  │ ◄── 모든 에이전트가 자유롭게 참조/누적
              └──────────────────────────┘
```

### 3.1 세 가지 핵심 구성 요소
1. **병렬 에이전트 (Parallel Agents)**: 독립적으로 작업 큐에서 태스크를 가져와 국소 추론(local reasoning) 수행.
2. **공유 컨텍스트 (Shared Context, $\mathcal{C}$)**: 검증된 컴팩트한 요약 정보(Gist)가 누적되는 영속적 문제 상태 기판.
3. **작업 큐 (Task Queue, $\mathcal{T}$)**: 의존성(dependency)을 인식하며 에이전트들이 비동기적으로 작업을 클레임하는 대기열.

### 3.2 5단계 파이프라인 (Execution Pipeline)
1. **$\text{Stage 1}$ (초기화)**: 입력 태스크와 소스 문맥을 기반으로 의존성을 가진 초기 서브태스크들을 생성하여 $\mathcal{T}$에 삽입.
2. **$\text{Stage 2}$ (병렬 실행)**: 사용 가능한 워커들이 $\mathcal{T}$에서 의존성이 해결된 작업을 비동기적으로 가져와 실행.
3. **$\text{Stage 3}$ (압축, 검증 및 진입)**: 완료된 결과 $r_i$를 컴팩트한 요약($G_i$)으로 압축하고, 검증 통과 시 $\mathcal{C}$에 원자적으로 추가.
4. **$\text{Stage 4}$ (추가 서브태스크 생성 / Replan)**: 작업 큐가 비었을 때, 가장 최근 작업을 마친 에이전트가 현재 $\mathcal{C}$의 정보가 충분한지 평가. 부족하면 추가 서브태스크를 큐에 인큐, 충분하면 종료로 이동.
5. **$\text{Stage 5}$ (최종화)**: 검증된 공유 컨텍스트 $\mathcal{C}$를 기반으로 최종 답변 생성.

## 4. DeLM의 핵심 아키텍처 및 메커니즘

### 4.1 3단계 계층적 표현 구조 ($r_i \rightarrow S_i \rightarrow G_i$)
운영체제(OS)의 가상 메모리 관리(Working Set & Paging) 원리를 컨텍스트 관리에 도입했습니다.

| 계층 | 명칭 | 저장 위치 | 내용 및 역할 |
| :--- | :--- | :--- | :--- |
| **$G_i$ (Gist)** | 요약 진입 항목 | 공유 컨텍스트 $\mathcal{C}$ | 약 100토큰 내외의 고도로 압축된 핵심 요약. 모든 에이전트가 항상 상주(resident)하여 확인하는 작업 셋. |
| **$S_i$ (Summary)** | 참조 접지 증거 맵 | 백킹 스토어 $\mathcal{L}$ | 원본 텍스트의 verbatim 앞/뒤 단어를 담은 **Ref-Tag**(`[ref: head ... tail]`)를 포함한 불릿 단위의 세부 증거 맵. |
| **$r_i$ / $u_i$ (Raw)** | 원본 데이터 | 백킹 스토어 $\mathcal{R}$ | 원본 문서 텍스트 전체 또는 에이전트의 전체 실행 트레이스. |

### 4.2 선택적 펼치기 (Selective Unfolding: 수요 페이징)
에이전트는 기본적으로 가벼운 $G_i$만 보며 작업하다가, 세부 정보가 필요할 때 단계적으로 요청합니다:
- **`UNFOLD: l_1, l_2` (Stage 1)**: 특정 라벨에 대해 $S_i$ 불릿 맵을 가져옴.
- **`DEEP_UNFOLD: l_1` (Stage 2)**: $S_i$로도 모호한 구체적 수치나 어구를 확인하기 위해 원본 $R$을 가져옴 (인접 청크 $n\pm 1$을 함께 가져와 경계 오차 보정).
- **공유 컨텍스트 오염 방지**: 펼쳐진 세부 원본 내용은 **해당 에이전트 호출의 로컬 프롬프트에만 임시로 주입**되며, 공용 $\mathcal{C}$에는 기록되지 않아 전체 컨텍스트 팽창을 원천 차단합니다.

### 4.3 진입 시점 검증 (Admission-Time Verification)
잘못된 가설이나 거짓 정보가 한 번 공유 상태에 들어가면 모든 다운스트림 에이전트를 오염시키므로, **진입 전에 반드시 검증**합니다:
- **추론 트레이스 검증**: $G_i$가 실제 성공/실패/제약사항을 왜곡 없이 담았는지 LLM Verifier가 검사.
- **긴 문서 소스 검증**:
  1. $S_i$의 Ref-tag($h, t$)가 원본에 글자 그대로 존재하는지 확인.
  2. 커버리지 루프(Coverage Loop): 참조되지 않은 공백 구간이 있으면 추가 불릿 생성 요구.
  3. $G_i$가 $S_i$를 바탕으로 환각이나 한정자(qualifier) 누락 없이 요약되었는지 경량 모델(DeepSeek-V4-Flash)로 검증.
  4. 실패 시 거절, 재작성, 또는 거절 사유와 함께 작업 큐로 반환.

### 4.4 시스템 최적화
- **원자적 쓰기(Write-before-publish) 및 Lock-Free 읽기**: 백킹 스토어($\mathcal{L}, \mathcal{R}$)에 먼저 쓴 후 $\mathcal{C}$에 $G_i$를 추가하여 레이스 컨디션 방지.
- **의존성 기반 작업 큐 및 데드락 방지**: 작업 간 선후 관계(`[deps: ...]`) 관리.
- **KV-Cache 재사용 극대화**: 변경되지 않고 점진적으로 추가되는 $\mathcal{C}$를 프롬프트의 가장 앞부분(접두사 prefix)에 배치하여 모델 호출 간 KV 캐시 히트율을 극대화함.

#### 높은 정확도와 50% 비용 절감의 3가지 원인 (트레이스 분석)
1. **실패 경험의 공유 (Sharing Failures)**:
   - 예: Sympy `lambdify` 튜플 버그에서 스레드 `t0`이 파이썬 프린터 계층 수정이 무효함을 `[t0/FACT]`로 남기자, `t1`은 프린터 삽질을 건너뛰고 `_recursive_to_string`의 실제 버그 위치를 즉시 찾아냄.
2. **구속력 있는 제약조건의 보존 (Binding Constraints)**:
   - 예: Django ORM에서 `filter(A).filter(B)`를 단일 호출로 합치는 최적화 시, M2M 다중값 관계에서 동작이 깨진다는 제약 `[t3/FAIL]`이 보존됨. 중앙집중식에서는 메인 에이전트가 이를 "대부분의 케이스엔 유효하다"며 절충안으로 희석하여 실패했으나, DeLM은 제약조건이 그대로 유지되어 안전한 최적화 코드를 작성함.
3. **압축된 패치 요약 공유 (Compact Patch Summaries)**:
   - 파일 덤프, bash 실행 로그, 에러 스택을 전부 공유하는 대신 `[t1/PATCH_SUMMARY]` 형태로 압축된 증거 기반 결론만 공유하여, 정보 가치는 보존하면서 토큰 비용을 대폭 삭감함($0.399 $\rightarrow$ $0.125).

### 5.2 LongBench-v2 Multi-Doc QA (긴 문맥 다중 문서 질의응답)

4개 프론티어 모델 모두에서 최고 성능 기록 (3회 반복 평균):

| 백본 모델 | Base | Claude Code | ReadAgent | **DeLM (Ours)** | 베이스라인 대비 향상 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **GPT-5.4** | 53.9% | 54.4% | 53.0% | **60.1%** | **+5.7%p** |
| **Claude Sonnet 4.6** | 53.3% | 51.7% | 54.5% | **59.8%** | **+5.3%p** |
| **Gemini 3 Flash** | 57.1% | 49.5% | 54.9% | **61.5%** | **+4.4%p** |
| **DeepSeek-V4-Pro** | 63.9% | 58.0% | 46.8% | **67.5%** | **+3.6%p** |

#### Ablation Study (구성 요소 기여도 분석)
- **검증 단계 제거 (No Verification)**: 정확도 60.1% $\rightarrow$ **55.2%**로 급락 (검증되지 않은 수치 왜곡 주장이 다른 에이전트에게 전파되어 전체 추론 붕괴).
- **계층적 요약 제거 (No Hierarchical Summary)**: 정확도 60.1% $\rightarrow$ **57.7%**로 하락 ($G \rightarrow raw$ 직접 점프는 지나치게 많은 원본 청크를 펼치게 만들어 비효율 초래).
- **Gist 길이 영향**: 50토큰(58.3%) $\rightarrow$ 100토큰(60.1%)으로 오르며, 150토큰(60.3%)에서는 포화됨 (100토큰이 최적).
- **요약기 모델 비용 영향**: 저렴한 DeepSeek-V4-Flash(60.1%)를 써도 GPT-5.4(59.9%)나 DeepSeek-V4-Pro(60.4%)와 대등함 $\rightarrow$ **요약/검증에는 초경량 모델을 사용하여 비용 효율을 극대화할 수 있음**.

---

### 5.3 OOLONG 벤치마크 및 RLM 결합 (정형 코드 실행과의 시너지)

OOLONG은 타임스탬프와 사용자 속성이 붙은 대규모 데이터에서 정밀한 개수 세기, 필터링, 정렬 등 **코드 실행(REPL) 집계**가 필수적인 벤치마크입니다.

| 방법론 | OOLONG 정확도 | OOLONG 비용 | LongBench-v2 정확도 | LongBench-v2 비용 |
| :--- | :---: | :---: | :---: | :---: |
| **RLM** (단일/중앙집중식 REPL) | 56.0% | $0.43 | 55.8% | $0.29 |
| **DeLM** (자연어 공유 컨텍스트) | 53.3% | $0.47 | 57.9% | $0.30 |
| **DeLM + RLM (하이브리드)** | **64.0%** | **$0.40** | **60.3%** | **$0.24** |

- **시사점**: DeLM의 공유 컨텍스트/작업 큐는 자연어 대화형 에이전트에만 국한되지 않음. 정밀한 프로그래밍 기반 REPL 도구를 가진 RLM 에이전트들을 DeLM의 탈중앙화 기판 위에서 조율하면, **정확도 상승(+8.0%p)과 비용 절감(-$0.03)을 동시에 달성**함.

## 6. 한계점 및 향후 전망 (Discussion)

1. **검증 오버헤드**:
   - 진입 시점 검증 호출로 인한 약간의 레이턴시 발생. 규칙 기반(rule-based) 체크나 초경량 전용 검증 모델로 추가 경량화 가능.
2. **서브태스크 분해 품질 의존성**:
   - 초기의 작업 쪼개기가 지나치게 거칠거나 세분화되면 효율이 저하될 수 있음. 공유 상태에 따라 동적으로 태스크를 합치거나 분할하는 적응형 분해 에이전트 연구 필요.
3. **자동화된 과학 연구 시스템(Automated Research)으로의 확장**:
   - SkyDiscover, AlphaEvolve 등 과학 연구 에이전트들은 수많은 논문 검토와 코드/실험 가설 탐색을 병렬로 수행함.
   - DeLM의 검증된 공유 컨텍스트 구조는 에이전트들이 같은 논문을 중복 읽거나 실패한 실험을 중복 실행하는 낭비를 방지하는 최적의 프레임워크가 될 수 있음.

## 7. 핵심 결론 (Takeaway)

> **"다중 에이전트 시스템을 효과적으로 스케일링하기 위해서는 단순히 더 많은 에이전트를 띄우는 것보다, 그들이 발견한 진전을 손실 없이 공유할 수 있는 '신뢰할 수 있고 컴팩트한 공유 상태 기판'을 제공하는 것이 결정적이다."**

- 중앙 집중식 컨트롤러의 병목을 없애고 **비동기 작업 큐 + 검증된 공유 컨텍스트**로 대체.
- **Gist $\rightarrow$ Summary $\rightarrow$ Raw** 계층적 펼치기로 컨텍스트 윈도우 낭비 최소화.
- 소프트웨어 엔지니어링(SWE-bench) 및 장문 추론(LongBench)에서 **더 높은 정확도와 현저히 낮은 비용(최대 50% 절감)**을 동시에 증명함.
